테렌스 타오의 「Math 2.0」 강연에는 답을 얻는 것과 그 답을 이해하는 것의 차이를 짚는 대목이 있다. NoteOn에서 이 대목은 강의 노트 5장에 있다. 제목 옆 **21분 25초**를 누르면 설명에 해당하는 장면이 재생된다. 편집할 때는 이 시각이 정확한지 확인해야 하고, 화면을 만들 때는 독자가 읽던 문장을 놓치지 않고 영상을 볼 수 있게 해야 한다. [강연에서 해당 대목 보기](https://www.youtube.com/watch?v=aHpPoNNTOKY&t=1285s)

## 서비스 구성

편집자가 작성한 **강의 노트**는 같은 강의를 듣는 독자들이 함께 읽는다. **문장 메모**는 독자가 노트 속 문장을 선택해 남기는 개인 기록이다.

| 사용자 | 할 수 있는 일 |
|---|---|
| 편집자 | 영상과 자료를 대조해 구간별 해설을 쓰고 재생 시각을 붙인다. |
| 독자 | 강의 노트를 읽다가 궁금한 대목의 시각을 눌러 영상을 재생한다. |
| 로그인한 독자 | 강의를 북마크하거나 노트의 문장에 내 메모를 남긴다. |

## 아키텍처

모듈을 나눈 기준은 맡은 일이다. 예를 들어 **강의 조회**는 한 화면에 무엇을 보낼지 결정하고, **재생 제어**는 독자가 선택한 시각으로 플레이어를 옮긴다. 구간을 누를 때마다 서버에서 강의 한 편을 다시 읽을 필요가 없는 이유다.

<a href="/blog/media/noteon-how-it-works/layers.svg"><img width="800" height="507" src="/blog/media/noteon-how-it-works/layers.svg" alt="화면, 조회, 저장, 편집으로 묶은 모듈 구성. 화면은 표시와 재생을, 조회는 읽기와 조합을, 저장은 자료 보관을, 편집은 노트 작성과 검증 및 반영을 맡는다." loading="lazy" decoding="async"/></a>
<figcaption>같은 테두리 안의 모듈은 역할이 비슷하다. 편집은 노트를 고칠 때 실행하고, 화면과 조회는 독자가 강의를 이용할 때 실행한다.</figcaption>
</figure>

| 레이어 | 모듈과 책임 |
|---|---|
| 화면 | **강의 화면**이 영상 옆에 구간 목록과 노트를 배치한다. **재생 제어**가 구간 선택을 플레이어에 전달하고 현재 재생 시각에 맞는 자막을 표시한다. |
| 조회 | **강의 조회**가 요청받은 영상 ID로 강의와 과목을 고른다. **카탈로그 로더**는 과목·강의를 읽고 공식 챕터와 보충 노트를 합친다. **자막 조회**는 해당 영상에 공개할 수 있는 한국어 자막이 있는지 확인한다. |
| 저장 | **공개 카탈로그**에는 과목, 강의 노트와 재생 구간이 있다. **공개 자막**은 영상·언어별 파일이다. **개인 학습 기록**에는 독자의 북마크와 문장 메모가 남는다. |
| 편집 | **노트 편집**에서 영상과 자료를 대조해 초안을 쓴다. **초안 검사**가 필수 항목과 시각 범위를 확인한다. **변경 반영**은 검토한 내용을 개발용 카탈로그와 운영 DB에 적용할 형태로 만든다. |

구현에서 강의 조회와 카탈로그 조합은 Next.js 서버가 맡는다. 화면과 재생 제어는 React와 YouTube 플레이어 API로 구현했다. 과목·강의와 계정별 기록은 Supabase Postgres에 두고, 로그인은 Supabase Auth를 통해 처리한다.

## 데이터 모델

타오의 강연을 식별하는 값은 YouTube 영상 ID `aHpPoNNTOKY`다. 여기에 무엇을 더 붙이느냐에 따라 구간을 재생하거나 특정 독자의 문장 메모를 다시 열 수 있다.

<figcaption>재생 구간은 시간에, 문장 메모는 글 안의 위치에 연결된다. 둘을 같은 강의로 찾아가는 기준이 영상 ID다.</figcaption>

| 데이터 | 저장 단위 | 화면에서 쓰이는 방식 |
|---|---|---|
| 과목과 강의 | 과목 한 행에 여러 강의가 연결된다. 강의의 `course_id`는 소속 과목을, `position`은 과목 안의 순서를 가리킨다. | 같은 과목의 강의를 회차 순으로 보여 준다. |
| 노트와 출처 | 강의 행에 한 문장 요지, 문단별 요약, 개념 설명, 자료 링크와 작성 근거를 담는다. | 설명을 읽다가 그 근거가 된 자료를 열 수 있다. |
| 노트의 장과 발췌 구간 | 노트의 장(`chapters`)과 타임라인의 발췌 구간(`clips`)을 별도로 저장한다. 노트 5장에는 시작 1,285초와 끝 1,496초가 붙어 있다. | 같은 강의에서도 선택한 구간에 따라 재생 위치가 달라진다. |
| 한국어 자막 | 공개 가능한 트랙을 영상 ID와 언어별 파일로 관리한다. 자막 한 줄에는 시작·종료 밀리초와 본문이 들어간다. | 플레이어의 현재 시각에 맞는 한 줄을 표시한다. |
| 북마크와 선호 표시 | `study_entries`의 키는 사용자, 강의, 표시 종류의 조합이다. | 한 강의를 북마크한 뒤 좋아한 강의로도 표시할 수 있다. |
| 문장 메모 | `lecture_annotations`는 사용자와 메모 ID로 한 건을 식별한다. 강의 ID, 문단별 선택 범위와 원문, 메모 내용과 공개 여부를 함께 보관한다. | 강의를 다시 열면 표시한 문장에 메모가 붙는다. |

메모에는 선택 당시의 원문도 보관한다. 같은 문장이 한 문단에 두 번 나와도 위치로 구분하고, 편집으로 본문이 달라졌다면 저장해 둔 원문과 대조할 수 있다.

## 호출 흐름

### 강의 노트 제작

<figure>
<a href="/blog/media/noteon-how-it-works/curation-sequence.svg"><img width="800" height="579" src="/blog/media/noteon-how-it-works/curation-sequence.svg" alt="노트 편집, 초안 검사, 변경 반영, 공개 카탈로그 사이의 전달 순서. 편집자가 원본을 대조하고 검토된 내용만 반영한다." loading="lazy" decoding="async"/></a>
<figcaption>작성한 초안은 검사와 원본 대조를 거친다. 편집자가 미리보기에서 확인한 뒤에 운영 카탈로그에 반영한다.</figcaption>
</figure>

테렌스 타오의 「Math 2.0」에서 **21분 25초**는 노트의 다섯 번째 장이 시작되는 시각이다. 이 장에서는 수학 문제의 답을 얻은 뒤에도 연구자에게 어떤 이해가 필요한지 다룬다. 편집할 때에는 시간 정보가 붙은 영어 자막 245개 구간을 대조했다. 완성된 노트는 여섯 장과 복습 문제 일곱 개다.

1. **자료 준비.** 편집자는 영상 ID와 공식 자료를 맞춘다. 상세 노트 제작 도구는 검토 가능한 자막을 시간순으로 묶고 문단마다 원본의 시작 초를 남긴다. 이 자료와 기존 강의 노트, 출처 링크가 노트 편집의 입력이다.
2. **노트 편집.** Codex의 첫 번째 작업은 설명의 주제가 바뀌는 대목을 찾아 장을 나누는 일이다. 장마다 강연자의 사례를 한국어로 풀어 쓰고, 개념 설명과 복습 문제를 연결한다. 타오 강연의 다섯 번째 장은 1,285초에 시작해 다음 장이 열리는 1,496초에 끝난다.
3. **초안 검사.** 두 번째 Codex 작업이 같은 시간대의 자막과 초안을 나란히 읽으며 인명, 숫자, 예시, 그림의 근거를 대조한다. 수정한 노트를 기존 강의 데이터에 합치면 별도의 검사기가 장의 순서·시간 범위와 영상 길이 대비 설명 분량, 도식·복습 문제의 수를 확인한다. 여기까지의 산출물은 편집자가 열어 볼 수 있는 초안이다.
4. **변경 반영.** 편집자는 로컬 강의 화면에서 설명과 출처를 읽고 노트의 시각을 눌러 원본 장면을 확인한다. 변경은 로컬 카탈로그와 새 DB용 초기 데이터에 기록한다. 기존 운영 DB에는 수정 대상 필드가 편집 전 값과 일치할 때만 갱신하는 SQL을 적용한다. 마지막으로 공개 강의 화면에서 바뀐 노트와 재생 위치를 다시 확인한다.

### 강의 조회와 구간 재생

<figure>
<a href="/blog/media/noteon-how-it-works/lecture-sequence.svg"><img width="800" height="653" src="/blog/media/noteon-how-it-works/lecture-sequence.svg" alt="강의 조회가 카탈로그 로더와 자막 조회에서 받은 자료를 강의 화면에 전달한다. 노트의 시각을 누르면 재생 제어가 선택한 위치에서 재생한다." loading="lazy" decoding="async"/></a>
<figcaption>세로 방향은 시간, 가로 방향은 모듈 사이의 호출이다. 페이지를 열 때 서버 조회가 일어나고, 노트의 시각을 누를 때에는 화면 안에서 재생 위치가 바뀐다.</figcaption>
</figure>

1. **강의를 연다.** 강의 조회가 URL의 영상 ID 형식을 확인한다. 카탈로그 로더는 공개 카탈로그에서 과목과 강의를 읽는다. 요청한 강의가 목록에 없으면 여기서 404를 돌려준다.
2. **화면을 구성한다.** 시청 가능한 영상이면 강의 조회가 자막 조회를 호출한다. 강의 화면은 노트와 구간 목록을 받고, 재생 제어는 영상 ID와 구간 경계, 사용 가능한 자막을 받는다. 한국어 자막이 없는 강의도 영상과 노트는 그대로 열린다.
3. **노트 5장에서 21분 25초를 누른다.** 강의 화면이 선택한 장의 재생 범위를 재생 제어에 넘긴다. 재생 제어는 브라우저의 플레이어를 1,285초로 옮긴다. 노트는 그 자리에 남아 독자가 영상과 설명을 번갈아 볼 수 있다.

## 인프라

GitHub Actions에서 코드와 정적 데이터의 일치 여부를 검사하고 앱을 빌드한다. 운영에서는 Railway가 Next.js 앱을 Node.js 서비스로 실행한다. 영상 스트리밍은 YouTube가 맡는다. 바꾸려는 대상에 따라 배포 경로도 다르다.

| 바뀌는 것 | 반영되는 곳 | 확인할 결과 |
|---|---|---|
| 플레이어 UI, 페이지 코드, 번들에 포함된 자막·챕터 | Next.js 앱 빌드와 Railway 배포 | 새 화면에서 구간 이동과 자막이 맞는가 |
| 공개 과목·강의 행과 편집 노트 | Supabase Postgres 마이그레이션 | 운영 카탈로그에서 해당 회차와 근거 자료가 함께 보이는가 |
| 북마크와 문장 메모 | 로그인한 독자의 DB 행 | 다시 접속해 같은 계정으로 해당 강의를 열면 기록이 남아 있는가 |

## 화면 기획

홈은 최근 흥미롭게 본 HackerTube AI의 UI에서 출발했다. 무엇을 볼지 정하지 않은 날에는 영상을 둘러보고, 이미 공부하던 과목이 있으면 다음 회차로 바로 들어가고 싶었다. 그래서 과목 순서, 주제별 발췌, 검색이라는 세 입구를 두었다. 어느 입구로 들어와도 학습은 같은 강의 화면에서 이어진다.

강의 화면을 그릴 때는 스크롤 전후를 한 쌍으로 보았다. 처음에는 ‘어느 대목을 볼까’가 중요해서 영상 옆에 구간 목록을 두었다. 노트로 내려간 뒤에는 ‘방금 읽은 설명을 영상에서 확인할 수 있을까’가 중요해서 작은 플레이어와 목차를 곁에 남겼다.

### 디자인 원칙

- **색은 행동과 상태에 쓴다.** 영상 썸네일 자체에 색이 많아서 화면 바탕과 구분선은 회색 계열로 두었다. 주황색은 주요 동작과 현재 위치를 드러내는 데 쓴다.
- **읽는 폭과 재생 맥락을 함께 지킨다.** 본문은 한 줄이 지나치게 길어지지 않게 하고 한국어 단어 단위로 줄을 바꾼다. 좁은 화면에서는 목차를 접어 본문이 들어갈 자리를 확보한다.
- **떠 있는 요소만 떠 보이게 한다.** 본문과 구간 사이에는 가는 선을 쓰고, 작은 플레이어나 메모 창처럼 본문 위에 올라오는 요소에만 그림자를 준다.

## 권한과 데이터 보호

| 역할 | 할 수 있는 일 | 데이터 범위 |
|---|---|---|
| 방문자 | 강의를 찾아 재생하고 노트와 공개 문장 메모를 읽는다. | 과목과 강의가 모두 공개된 자료를 조회한다. |
| 로그인한 독자 | 북마크를 저장하고 선택한 문장에 메모를 쓴다. | 자기 계정의 기록을 읽고 고친다. 문장 메모는 기본 비공개이며, 작성자가 공유한 메모만 다른 독자에게 보인다. |
| 콘텐츠 편집자 | 출처와 재생 시각을 대조하고 검토한 노트를 카탈로그에 반영한다. | 공개될 강의 자료를 다룬다. 독자가 쓰는 문장 메모와는 저장 경로가 다르다. |

앞의 두 역할은 서비스의 로그인 상태이고, 콘텐츠 편집자는 발행 과정에서 맡는 일이다. 개인 기록에 대한 권한은 데이터베이스에서도 확인한다. Supabase의 행 수준 보안(RLS)이 로그인 세션의 사용자와 기록의 소유자를 대조한다. 작성자가 공유를 해제하면 해당 메모는 다음 공개 조회부터 빠진다.

### 사용자 행동

| 동작 | 기록 시점과 값 |
|---|---|
| 페이지 열기 | 화면 경로나 검색 조건이 바뀌면 페이지 조회를 기록한다. 검색어와 선택한 주제가 있으면 함께 보낸다. |
| 재생 시작 | 플레이어에 처음 재생을 요청할 때 시작 초와 진입 방식을 남긴다. 포스터를 눌렀는지 특정 구간에서 시작했는지 구분할 수 있다. |
| 구간 이동 | 노트나 타임라인에서 시각을 누르면 목표 시각과 누른 위치를 기록한다. 예를 들어 노트의 21분 25초를 누르면 시작 초는 1,285다. |
| 메모와 학습 기록 저장 | 메모 저장이 성공하면 공개 여부를, 북마크나 선호 표시가 바뀌면 종류와 설정·해제 여부를 남긴다. |
| 로그인 시작 | 로그인 절차를 연 위치를 기록한다. 북마크를 누르다가 로그인을 시작한 경우도 구별할 수 있다. |

수집을 켜면 브라우저가 이벤트를 모아 전송하고, 수집 API가 출처와 이벤트별 허용 속성을 확인한 뒤 저장한다. 방문과 세션을 구분하는 값은 브라우저에서 만든 임의의 ID다. 계정 ID·이메일·메모 본문은 전송 항목에서 제외한다. 브라우저에 추적 거부(DNT 또는 GPC)가 설정돼 있으면 이용 이벤트 전송을 건너뛴다.

이용량은 한국 시간 기준 하루 단위로 집계한다. 구간 이동은 최근 30일 동안 어느 강의의 몇 초를 어느 위치에서 눌렀는지까지 나누어 볼 수 있다. 같은 독자가 해당 문장을 세 번 누르면 이동도 세 건이다. 재생 시작은 재생을 요청한 횟수이므로 시청 시간이나 완강률을 측정하려면 다른 신호가 필요하다.

### 서버 로그와 상태 점검

서버는 OpenTelemetry로 요청 완료와 처리되지 않은 오류를 기록한다. 요청 완료 로그에는 경로 형식, HTTP 메서드, 응답 코드와 처리 시간이 들어간다. 예를 들어 서로 다른 강의를 여는 요청도 같은 강의 상세 경로로 묶인다. 오류 로그에는 발생 경로와 렌더링·요청 처리 등 발생 위치, 제한된 오류 유형이 남는다.

수집이 설정된 환경에서는 이 로그가 Supabase에 쌓인다. 운영할 때는 먼저 시간대별 요청 수, 4xx·5xx 응답 수, 처리되지 않은 오류 수를 본다. 응답 시간이 길어졌다면 최근 24시간의 로그를 경로별로 묶어 처리 시간의 중앙값(p50)과 95번째 백분위수(p95)를 비교한다. 중앙값이 비슷한데 특정 경로의 p95만 올라가면 그 경로에서 유독 오래 걸린 요청부터 살펴볼 수 있다. 서버 처리 시간의 측정 범위는 NoteOn이 요청을 처리한 구간까지다. 화면에서 영상을 누른 뒤 YouTube의 첫 프레임이 뜨기까지의 시간은 여기에 포함되지 않는다.
