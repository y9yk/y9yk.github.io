테렌스 타오의 강연을 읽다가 노트에 표시된 **21분 25초**를 누른다. 영상은 그 대목에서 재생되고, 방금 읽던 문장은 그대로 남아 있다. 여기에 내 메모를 써 두면 다음번에도 같은 문장에서 열 수 있다. 이 작은 동작이 내가 NoteOn에서 만들고 싶었던 학습 경험이다.

강의 한 편에는 서로 다른 세 가지 일이 일어난다. 먼저 편집자가 영상과 설명을 대조해 **공개 자료**를 만든다. 강의를 열면 서버가 그 자료를 **학습 화면**으로 조립한다. 마지막으로 독자가 남긴 **개인 기록**은 같은 강의를 가리키되 계정별로 저장한다.

## 데이터 모델 — 같은 강의, 서로 다른 좌표

영상 ID는 어느 강의인지 알려 준다. 그러나 타오의 강연에서 21분 25초를 다시 재생하려면 **영상 ID와 1,285초**가 필요하다. 문장 메모에는 또 다른 좌표가 필요하다. 누가 어느 문단의 몇 번째 글자부터 어디까지 선택했는지 알아야 같은 문장을 다시 표시할 수 있기 때문이다.

<figure>
<a href="/blog/media/noteon-how-it-works/hub.png"><img src="/blog/media/noteon-how-it-works/hub.png" alt="영상 ID를 중심으로 자막, 핵심 구간, 강의 노트, 메모와 학습 기록이 연결된 그림" loading="lazy" decoding="async"/></a>
<figcaption>재생 구간은 시간에, 문장 메모는 글 안의 위치에 연결된다. 둘을 같은 강의로 찾아가는 기준이 영상 ID다.</figcaption>
</figure>

| 데이터 | 저장 단위 | 화면에서 쓰이는 방식 |
|---|---|---|
| 과목과 강의 | 과목 한 행에 여러 강의가 연결된다. 강의의 `course_id`는 소속 과목을, `position`은 과목 안의 순서를 가리킨다. | 같은 과목의 강의를 회차 순으로 보여 준다. |
| 노트와 출처 | 강의 행에 한 문장 요지, 문단별 요약, 개념 설명, 자료 링크와 작성 근거를 담는다. | 설명을 읽다가 그 근거가 된 자료를 열 수 있다. |
| 발췌 구간 | 강의의 `clips` 배열에 시작·종료 시각을 초 단위로 기록한다. | 같은 강의에서도 선택한 구간에 따라 재생 위치가 달라진다. |
| 한국어 자막 | 공개 가능한 트랙을 영상 ID와 언어별 파일로 관리한다. 자막 한 줄에는 시작·종료 밀리초와 본문이 들어간다. | 플레이어의 현재 시각에 맞는 한 줄을 표시한다. |
| 북마크와 선호 표시 | `study_entries`의 키는 사용자, 강의, 표시 종류의 조합이다. | 한 강의를 북마크한 뒤 좋아한 강의로도 표시할 수 있다. |
| 문장 메모 | `lecture_annotations`는 사용자와 메모 ID로 한 건을 식별한다. 강의 ID, 문단별 선택 범위와 원문, 메모 내용과 공개 여부를 함께 보관한다. | 강의를 다시 열면 표시한 문장에 메모가 붙는다. |

메모에는 선택 당시의 원문도 보관한다. 같은 문장이 한 문단에 두 번 나와도 위치로 구분하고, 편집으로 본문이 달라졌다면 저장해 둔 원문과 대조할 수 있다.

## 아키텍처 — 서버가 조립하고 브라우저가 재생한다

<figcaption>강의 페이지를 기준으로 본 코드 구성. 페이지는 필요한 데이터를 요청하고 플레이어와 노트에 각각 쓰일 값을 건넨다.</figcaption>

| 레이어 | 기술 | 맡은 일 |
|---|---|---|
| 페이지 요청 | Next.js 16 App Router, TypeScript | 홈·주제·강의·내 학습의 URL을 해석한다. 강의 페이지는 서버에서 영상 ID로 필요한 자료를 고른다. |
| 화면과 상호작용 | React 19, YouTube 플레이어 API | 서버에서 받은 구간과 자막을 표시하고, 독자가 누른 시각으로 재생 위치를 옮긴다. |
| 데이터 조합 | TypeScript의 `lib/catalog.ts` | 과목과 강의를 읽고, 편집한 노트와 공식 챕터를 합쳐 페이지에 전달한다. |
| 저장과 인증 | Supabase Postgres, Supabase Auth와 Google 로그인 | 공개 카탈로그를 저장하고, 로그인한 독자의 학습 기록은 계정별로 읽고 쓴다. |

운영에서 `getCatalog()`는 공개 권한으로 과목과 강의를 병렬 조회한다. 어느 쪽에서 읽든 공식 챕터와 보충 노트를 붙이는 과정은 같다. 개발 중 두 연결 설정이 모두 비어 있으면 체크인된 카탈로그 스냅샷을 읽는다. 운영에서 조회가 실패하면 오류를 드러내므로 오래된 스냅샷이 최신 강의처럼 보일 일이 없다.

## 콜 플로우 — 편집할 때와 공부할 때

### 강의 자료가 카탈로그에 들어가기까지

<figure>
<a href="/blog/media/noteon-how-it-works/pipeline.png"><img src="/blog/media/noteon-how-it-works/pipeline.png" alt="공식 영상에서 출처가 있는 초안을 만들고 검사와 원본 대조를 거쳐 로컬 카탈로그와 운영 DB에 반영하는 흐름" loading="lazy" decoding="async"/></a>
<figcaption>편집 경로. 로컬 미리보기와 운영 반영은 같은 검토 결과에서 출발한다.</figcaption>
</figure>

1. 공식 영상의 ID와 학기·회차로 대상을 고른 뒤, 그 회차의 슬라이드와 공식 챕터를 맞춘다.
2. 설명과 출처를 노트에 담는다. 발췌 구간에는 직접 확인한 시작·종료 시각을 붙인다. 시점이 불확실한 설명에는 재생 링크를 만들지 않는다.
3. 초안 검사로 필드와 시간 범위를 확인한다. 이어서 원본 영상을 열어 해당 초에 실제로 그 설명이 나오는지 대조한다. 영상 길이 안에 있는 시각도 엉뚱한 장면을 가리킬 수 있기 때문이다.
4. 로컬 카탈로그로 화면을 확인한 뒤 기존 운영 DB에 조건부 SQL 변경을 적용한다. 마지막 확인은 독자와 같은 경로에서 한다. 노트의 시각을 눌러 의도한 장면이 나오는지 보는 것이다.

### 독자가 강의를 열고 구간을 누르기까지

<figure>
<a href="/blog/media/noteon-how-it-works/lecture-sequence.svg"><img src="/blog/media/noteon-how-it-works/lecture-sequence.svg" alt="브라우저의 강의 요청, Next.js의 카탈로그 조회, DB 응답, 강의 화면 전달 순서. 이후 구간 재생은 브라우저에서 처리한다." loading="lazy" decoding="async"/></a>
<figcaption>위에서 아래로 읽는 호출 순서. 마지막 화살표가 브라우저로 돌아오는 것은 재생 위치를 브라우저 안에서 바꾸기 때문이다.</figcaption>
</figure>

홈에서 강의를 고르면 Next.js가 URL의 영상 ID를 확인하고 강의와 소속 과목을 찾는다. 공개 카탈로그에 없는 ID라면 404로 끝난다. 시청 가능한 강의라면 공개 가능한 한국어 자막 트랙도 확인한다. 플레이어는 구간 경계와 자막을, 타임라인은 구간 목록을, 노트는 강의 본문을 받는다.

이제 21분 25초를 누르면 브라우저가 플레이어를 1,285초로 옮긴다. 자막이 있는 강의라면 현재 재생 위치에 맞는 줄도 바뀐다. 반면 북마크를 누르면 로그인 세션으로 저장소에 쓰기가 일어난다. 그래서 구간 이동은 즉시 일어나고, 북마크는 다른 기기에서 같은 계정으로 돌아와도 남는다.

## 인프라 — 무엇을 어디에 배포하나

첫 구성도의 경계는 실제 배포 단위이기도 하다. GitHub Actions는 코드와 정적 데이터의 일치 여부를 검사하고 Next.js 빌드를 실행한다. Railway에서는 빌드한 앱을 Node.js 서비스로 실행한다. 강의 페이지를 조립하는 곳은 이 서버이고, 영상 바이트를 독자에게 보내는 곳은 YouTube다.

| 바뀌는 것 | 반영되는 곳 | 확인할 결과 |
|---|---|---|
| 플레이어 UI, 페이지 코드, 번들에 포함된 자막·챕터 | Next.js 앱 빌드와 Railway 배포 | 새 화면에서 구간 이동과 자막이 맞는가 |
| 공개 과목·강의 행과 편집 노트 | Supabase Postgres 마이그레이션 | 운영 카탈로그에서 해당 회차와 근거 자료가 함께 보이는가 |
| 북마크와 문장 메모 | 로그인한 독자의 DB 행 | 다시 접속해 같은 계정으로 해당 강의를 열면 기록이 남아 있는가 |

## 화면 기획 — 재생에서 읽기로 넘어가는 순간

홈은 최근 흥미롭게 본 HackerTube AI의 UI에서 출발했다. 무엇을 볼지 정하지 않은 날에는 영상을 둘러보고, 이미 공부하던 과목이 있으면 다음 회차로 바로 들어가고 싶었다. 그래서 과목 순서, 주제별 발췌, 검색이라는 세 입구를 두었다. 어느 입구로 들어와도 학습은 같은 강의 화면에서 이어진다.

강의 화면을 그릴 때는 스크롤 전후를 한 쌍으로 보았다. 처음에는 ‘어느 대목을 볼까’가 중요해서 영상 옆에 구간 목록을 두었다. 노트로 내려간 뒤에는 ‘방금 읽은 설명을 영상에서 확인할 수 있을까’가 중요해서 작은 플레이어와 목차를 곁에 남겼다.

### 화면에서 확인할 수 있는 디자인 원칙

- **색은 행동과 상태에 쓴다.** 영상 썸네일 자체에 색이 많아서 화면 바탕과 구분선은 회색 계열로 두었다. 주황색은 주요 동작과 현재 위치를 드러내는 데 쓴다.
- **읽는 폭과 재생 맥락을 함께 지킨다.** 본문은 한 줄이 지나치게 길어지지 않게 하고 한국어 단어 단위로 줄을 바꾼다. 좁은 화면에서는 목차를 접어 본문이 들어갈 자리를 확보한다.
- **떠 있는 요소만 떠 보이게 한다.** 본문과 구간 사이에는 가는 선을 쓰고, 작은 플레이어나 메모 창처럼 본문 위에 올라오는 요소에만 그림자를 준다.

## 보안과 운영 — 누가 볼 수 있고, 무엇을 측정할까?

강의를 읽는 권한과 그 강의에 남긴 메모를 읽는 권한은 다르다. Supabase의 행 수준 보안(RLS)은 DB가 요청자의 권한에 따라 읽거나 쓸 수 있는 행을 제한하는 장치다.

| 독자가 하는 일 | 접근 범위 |
|---|---|
| 강의 열기 | 과목과 강의가 모두 공개된 경우에 공개 카탈로그에서 읽는다. |
| 북마크·메모 저장 | 로그인 세션의 사용자 ID로 본인 기록에 쓴다. 문장 메모의 기본값은 비공개다. |
| 다른 독자의 문장 메모 열기 | 작성자가 공개한 메모만 공개 조회 경로로 읽는다. 비공개로 돌리면 다음 조회부터 제외된다. |

**서버가 느린가?** 서버에서는 OpenTelemetry로 요청 경로 유형, 응답 코드, 처리 시간을 기록한다. 응답 시간 분포가 길어졌다면 트레이스로 요청 흐름을 보고, 오류 건수와 구조화 로그를 함께 확인한다. 이 신호가 설명하는 범위는 NoteOn 서버가 요청을 처리한 시간까지다. YouTube 영상이 독자의 기기에서 재생되기까지 걸린 시간은 별도 측정 대상이다.

**구간 이동이 쓰이는가?** 수집이 켜져 있으면 브라우저는 재생·구간 이동·메모 저장처럼 정해 둔 동작을 모아 전송한다. 수집 API는 허용된 이벤트와 속성을 확인한다. 계정 ID, 이메일, 메모 본문은 전송 대상에서 제외하며 DNT나 GPC가 켜져 있으면 브라우저 이벤트를 보내지 않는다. 따라서 구간 이동 횟수는 관측된 동작 수이다. 같은 독자가 한 구간을 여러 번 다시 보는 것도 여기에 포함된다.

처음의 21분 25초로 돌아가 보자. 편집할 때는 원본과 대조할 근거이고, 카탈로그에서는 숫자 1,285이며, 화면에서는 누를 수 있는 시각이다. 이 세 표현이 같은 장면을 가리켜야 독자는 설명을 읽다가 근거로 돌아갈 수 있다. NoteOn을 개발하면서 가장 중요하게 지키려 한 연결이다.
